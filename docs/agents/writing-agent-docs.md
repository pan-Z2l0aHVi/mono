# Agent 文档写作判据

本文件规定新增或修改 agent 文档与指令时的判断：一条约束放在哪里、写成什么形状、删除前要确认什么。context 分层、权威归属、同步义务与冲突处置以 [`agent-context.md`](./agent-context.md) 为准，本文件只补写作判据。环境提供 `writing-for-agents` skill 时按其方法执行；本页是仓库内的最小判据，两者冲突时以仓库规则与本页为准。

## 权威与指针

- 一条约束只有一个权威；其他位置只写何时加载，并指向该权威的具体小节。指针落到文件根算没写完：读者点开要能直接看到判据。
- 同一主题出现两份完整表述时，先定权威，另一处改成指针。

## 落点与删除

- 删除前先确定内容迁往哪个权威或哪个指针；没有落点的约束保留，并标明归属待定。
- 删副本不等于删约束：权威未承接前，删除会让约束消失。

## 写什么

- 写只能由人判断的约束：取舍原因、非显然的边界、跨处关联、工具判断不了的约定。
- 状态量（规模、成员、清单长度）与内部实现名（私有符号、调用顺序）不进指令面；需要时指向代码、生成物或配置。
- 易变参数（超时、重试、版本、阈值）不抄进文档；指向定义它的配置或脚本。
- 能由类型、测试、lint 或仓库校验判定的属性，文档不复述判据，只写脚本判断不了的部分。

## 怎么写

- 可判定：每条指令写出触发条件与判定标准，能判断做到或没做到；判定不了的句子改写或删除。
- 入口只承载触发条件与硬边界；操作步骤、环境准备、算法归专门文档或 skill，入口给指针。
- skill 的 `description` 写何时加载，不写能力清单；同类触发合并，不同分支才各留一条。

## 准入与冲突

- 新增前先确认现有权威承载不了，再确认入口路由能找到它；未被路由覆盖的文档不生效，与不存在等价。
- 与实现冲突时以实现为准；优先级与处置见 [`agent-context.md`](./agent-context.md#权威性与冲突处理)。
