# 客户端运行环境

这份文档只回答一个问题：agent 客户端跑在什么权限下。工具链自身的机制（mise、turbo、Go 缓存）在 `worktree.md`，包级构建配置在 `build.md`，都不在这里重复。

## 权限

客户端权限由机器级配置决定，不属于仓库政策。仓库不携带该配置，本地 task 台账也无法证明运行时权限；配置在会话启动时读取，改完只影响新开的线程。判断线程实际跑在什么权限下，看配置与线程的实际行为，不要凭 profile 名或记忆里的参数推断。

当前这台机器使用全访问模式，残余的审批请求交给自动评审而不是人。原因是 worktree 自己的 admin 目录按名字受保护，沙箱下 `git add` 与 `git commit` 会被拒，线程会反复停在审批；代价是隔离退回到仓库 checks、Git 禁令和目录纪律，没有运行时保证。这是对官方推荐的主动偏离，换机器或换客户端时应重新评估。

不要用在 CLI 层覆盖配置的参数来改变沙箱；要自动评审就配置审批路由，而不是把审批策略当成沙箱的配套。
