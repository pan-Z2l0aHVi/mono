# 客户端权限与运行环境

客户端配置、宿主策略和当前会话的权限共同决定可用操作。不要根据仓库配置推断当前会话一定拥有某种沙箱或网络权限；以客户端提供的实际权限和工具结果为准。

## 仓库配置

[`.codex/config.toml`](../../.codex/config.toml) 与 [`.claude/settings.json`](../../.claude/settings.json) 是仓库级配置。Codex 配置的加载受客户端和项目受信任状态影响；Claude 的 `permissions.deny` 限制相应工具调用。机器级设置由各机器自行管理，不属于仓库的权威配置。

生成物不得手工编辑。Claude 的 `deny` 不覆盖所有 shell 或脚本调用，也不代替沙箱、仓库规则或 review。由 generator 写入生成物仍须核对结果。

## 执行与授权

- 先检查当前会话实际提供的文件系统、网络和审批权限。工具被拒绝时保留错误，不把配置文件中的期望当作已生效的权限。
- 不得自行修改 Git 配置、客户端共享配置或权限设置。共享配置变更和其他需授权操作按 [`workflow.md`](./workflow.md#预授权操作) 执行。
- 沙箱允许某项操作不等于用户已授权；需要逐次授权的操作仍须取得授权。
- 权限不足时先完成不受影响的工作，再报告被阻塞的操作和原因。
