# Agent 任务提示协议

本指南把用户任务压缩成 agent 可执行的最小输入。不要在 prompt 中复制仓库规则、源码或整篇文档；那些内容由根入口和任务路由提供。只有仓库无法发现的业务决策、兼容要求、设计参考或期限才放入 prompt。

## 模板

```md
目标：
<一句话描述用户/工程结果>

范围：

- 可修改：<目录、包或明确文件>
- 不可修改：<明确边界；否则写“遵守仓库 AGENTS.md 边界”>

成功标准：

- <可观察的行为 / API / UI 结果>
- <必须通过的命令或浏览器验证>
- <必须同步的测试、文档或变更记录>

仅补充不可发现的背景：

- <业务决策、兼容要求、设计参考或期限>

工作方式：
先探索受影响区域与适用的 AGENTS.md，给出简短计划。
低风险实现可自主完成；公共 API、跨包架构、依赖/构建/发布决策或需求冲突时先询问。
完成时报告修改内容、验证命令与结果、浏览器证据（如适用）及残余风险。
```

## 分支隔离模板

并行 agent 不能共享一个会被切换分支的工作目录。需要指定隔离工作区时追加：

```md
工作区隔离：
本任务只能在 `<branch>` 的独立 worktree 中执行。
不得切换、暂存、重置、清理或修改 `<other-branch>` 的工作目录；
不要将该分支的未提交 diff 作为本任务的输入或验收对象。
```

## 当前仓库示例

```md
目标：
修复 @greypan/web-ui 的 Select 在 portal 模式下按 Escape 后焦点未回到触发按钮的问题。

范围：

- 可修改：packages/web-ui，以及必要的 React/Vue demo 验证代码
- 不可修改：生成文件、registry/mirror、Git 配置

成功标准：

- Escape 关闭后，键盘焦点回到原触发元素
- 不破坏现有 overlay / portal 行为
- 补充最小测试；运行目标包测试
- 在真实浏览器 demo 中完成键盘验证，并报告 URL、操作步骤和 console 状态

工作方式：
先读取适用的 AGENTS.md、web-ui 指南、现有 overlay/select 测试和当前实现。
若需要改变公共事件或属性契约，先提出方案；否则自主实现和验证。
完成时报告修改内容、验证命令与结果、浏览器证据及残余风险。
```

## 质量检查

- 目标必须描述结果，不只描述实现手段。
- 范围必须能通过 diff 检查。
- 成功标准必须能通过测试、构建、浏览器操作或人工审查复核。
- 不把“请仔细”“确保高质量”等不可判定措辞当作验收条件。
- 不用 prompt 覆盖仓库规则；若需要改变规则，应修改权威文档并同步 ADR/评测。
