都在这里按批次逐条列出。它是 [`../BATCH-LEDGER.md`](../BATCH-LEDGER.md)（批次级摘要）的下层，

## 怎么读

1. 每份 `batch-N.md` 的删除清单是**表驱动**的：一行一个（或一组）用例，核心信息是
   **位置**、**判据类别**（D1–D5 / C1–C8 / S1–S6 / R1–R4）、**删除理由**、**存活覆盖位置**。
2. 「存活覆盖位置」为空或写「不承接」的行，即有意放弃的覆盖，汇总在
   [`../BATCH-LEDGER.md`](../BATCH-LEDGER.md) 的「有意放弃的覆盖」一节。
3. **各批的列名与定位粒度不完全统一**（这 8 份是跨度 6 周陆续写成的，判据本身也在演进）：
   - Batch 1 / 3 / 5：`文件:行` 或 `file:line` 定位到行；
   - Batch 6a / 6b / 6c：`位置（基线）` 定位到行或到文件；
   - Batch 2 / 4：以`文件` + `用例标题`定位，不带行号（Batch 2 的 §4 逐文件清单另有「行」列）。
   - Batch 2 的 §3 删除清单只有「文件 / 用例 / 理由」三列，**存活覆盖不单列**，写在 §4 各文件的处置注记里。
     凡是带行号的，行号都是**该批次基线**（表内注明的 base 提交）下的行号，不是当前 HEAD 的行号——
     被删用例已不在树上，行号只对基线快照有意义。
4. 7 份文件带「独立审查结论」章节，是每批 freeze → review → approve 闸门的原始记录：
   Batch 1 §8.6 / §8.7、Batch 2 §9.5、Batch 3 §8、Batch 4 §9、Batch 5 §7、Batch 6a §8、Batch 6b §8。
   **`batch-6c.md` 没有这一章节**（止于 §9 转出项）——Batch 6c 的闸门记录只在工作流状态里：
   `pnpm agent:workflow status --task web-ui-contract-b6c`（状态存本地 `.git/agent-workflow/`，不随仓库分发）。

## 边界

这些文件是**过程记录**，不是新判据：判据以 [`../DELETION-RUBRIC.md`](../DELETION-RUBRIC.md) 为准，
批次记录中若出现与判据不一致的措辞，以判据为准并请订正记录。
