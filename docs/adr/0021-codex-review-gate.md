# ADR-0021: Codex 自动 PR 审查门

- **Date**: 2026-11-04
- **Status**: 已接受

## 背景

人工独立 review 是合并前的主要质量关口，但它要等人，而且对同一份 diff 的低级遗漏并没有分工价值。仓库已经有 PR CI，把一次模型审查挂在 CI 之后不需要新的基础设施。

难点不在「能不能跑模型」，在三处：

- PR 验证的 workflow 在仓库里被机器判定为只读，而审查结论要写回 PR。
- 被审查的改动与被审查代码同处一个 worktree，模型读到的东西可能被这次改动改写。
- 模型输出是概率性的，一道红绿不定的门不会被接受。

## 决策

Codex 审查是对 [ADR-0012](./0012-pr-review.md) 的补强，不是替代：绿色 CI 不证明 review 完成，模型结论也不证明人工独立 review 已完成。

**门禁形态**：约定式门禁，不改 GitHub 分支保护。只有 `Block` 档发现让这道门变红；`unreviewed` 与 `stale` 保持绿色，但必须与 `Block` 数量一起写进 PR 上同一条持久评论。合并准入仍由人和仓库的 PR review 纪律决定。

**权限分腿**：模型只在 PR 验证的只读 job 里运行；写回（评论、应用并推送 patch）在由 CI 完成事件触发的独立 workflow 里进行，那条 workflow 一次都不调用模型。这条划分是 PR 验证只读不变量成立的前提。

**沙箱档位**：使用 action 的 legacy `sandbox` 输入（`--sandbox`），不使用权限档输入。本仓 `.codex/config.toml` 在 project 层写死全访问；`--sandbox` 覆盖的是同一个配置键，权限档落在另一个键上，无法证明它能压过 project 层。CI 定义由机器断言钉住这个选择。

**输入可信来源**：prompt、schema、判定脚本与生成物禁令清单从 PR base（写腿从默认分支）取版本落到 runner 临时目录，执行只用那份副本。工作区本身仍检出 PR head：`uses: ./...` 的复合 action 由 job 工作区解析，检出 base 会让本 PR 新建的 action 解析不到，这道门整个跑不起来——固定的是脚本内容的来源，不是工作区的来源。残留的篡改面是 workflow YAML 与 PR 腿由工作区解析的复合 action（`setup-deps` 与 `stage-codex-inputs`，前者还先于后者运行）：它们必须由 head 提供，所以改它们仍在被审查的 diff 里明写，与「模型能读到 worktree 里的 review 判据文档」归在同一类已接受风险里，由人工 review 和「只审同源仓库、base 为 `main`」的范围一起兜住。CI 定义由机器断言同时钉住工作区来源与 `base-sha` 这两侧。

**适用范围**：只审合同源仓库、base 为 `main`、未关闭且不是版本分支的 PR。fork PR 默认不跑——它拿不到仓库 secret，要审就得逐次为它放行。

**幂等与去重**：同一 head 已有结论时复用前一次 run 的产物，标题编辑与手动重跑不再消耗模型调用；并发组按 PR 分支取消更早的 run。不设文件数、行数或改动量阈值，也不给模型加「只看 N 个文件」的采样——体量问题用超时兜住，而不是用少看来兜。

**自动修**：`check` job 失败时，模型在 workspace 沙箱里产出一份候选 patch，作为 artifact 交给特权腿；只有它校验通过才提交并直推 PR 分支。patch 只能修改已入库文件，CI 定义、依赖清单、生成物、agent 指令与凭证路径一律整份拒绝。已包含自动修提交的 head 不再规划第二次。

**时间与成本**：两条模型腿各给 60 分钟上限，这是首批实测用的临时余量，测出真实分布后回收；自动修只在失败时触发，它自己也是消耗模型调用的一条腿。

**端点与密钥**：API key 只放 GitHub Secrets，地址放公开 vars，二者都不写进 CI 定义；调用经由 action 自带的本地代理，模型进程拿不到密钥本身。

## 后果

- 自动修推送的新提交不会触发 checks，PR 上那道必需检查要人重跑一次 CI 才会覆盖新 head；结论对新 head 也随之过期，这是「直推」换来的代价。
- 门是约定式的：绕开它只需要忽略一次红叉，因此它省的是「等一次人工细看」，不是「替代人工」。
- 只读腿与写腿分居两个 workflow，读代码时看到的 YAML 不能解释全部行为；判据在 ADR 与机器断言里，不只在 CI 定义里。
- 模型结论的可信度受沙箱档位与输入版本影响，这两处都由 CI 拓扑测试钉住，改动会被断言挡下来，而不是靠 review 时想起来。
- 首批实测要回答两个此前只能推断的问题：Linux 上 `--sandbox` 是否如文档生效，以及 60 分钟余量对应多大的真实耗时。
