# Overlay interaction policy

`no-scroll-lock` opts out of background-document scroll prevention without implying modal semantics; overlay-local scroll regions remain usable. Dialog remains natively modal; Select, Dropdown, and Context Menu expose `no-scroll-lock`, while Popover and Tooltip never lock scrolling. A live `no-scroll-lock` change takes effect immediately. Select keeps focus on its combobox trigger and exposes the selected option, or the first enabled option, through `aria-activedescendant` when it opens. Dropdown and Context Menu use cyclic arrow-key navigation, Home/End, Right/Left submenu navigation, Enter/Space activation, and one Escape press closes only the deepest open menu level. Popover focuses only its first enabled `[autofocus]` descendant; otherwise it retains trigger focus and restores that focus on close only when focus remains inside the panel. Each overlay follows an explicit component-specific focus model so focus ownership is not inferred from scroll locking.
