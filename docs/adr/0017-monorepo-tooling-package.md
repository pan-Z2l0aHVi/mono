# ADR-0017: 门禁与仓库工具收敛到 workspace 包

- **Date**: 2026-10-28
- **Revised**: 2026-11-06
- **Status**: 已接受

## 背景

迁移前根 `scripts/lib/` 同时装着三类职责：门禁原子实现、本仓编排（端口分配、共享缓存路径）与仓库无关的纯工具。它们的消费者、变更频率与失败语义不同，却共用一个目录与一套测试发现机制，由此有三个已发生的问题：

- **跨包引用深度不一致**：workspace 配置引用 `scripts/` 要走 `../../..` 级相对路径，各包深度不同，迁移时曾写出一批 `TS2307`；包 specifier 没有这一维。
- **测试没有归属**：全仓 `*.test.mjs` 由脚本入口串行直跑，无缓存、无并发、失败只报文件名；包测试在 turbo 图里有依赖排序、缓存与按包定位失败。
- **依赖边不可见**：「谁消费端口表」只能靠 grep 相对路径，manifest 里没有边，`pnpm why` 看不到。

## 决策

新建私有包 `@greypan/monorepo-kit` 承载门禁与仓库工具，三类职责由包名而不是目录位置给出身份。

包的 `exports` 是一小撮数得清的 specifier，没有按目录粒度的通配子路径，所有消费点经包名引用；没有自由子路径，就没有「子路径拼错」与「新增分区忘了加通配」两类错误。入口只有 `.`（Node 脚本）与 `./vite`（Vite 求值期适配）两个，形状由 [ADR-0022](./0022-monorepo-kit-plugin-chain.md) 收窄；内部平铺导出，判据是导出名是否冲突。

`scripts/lib/` 收缩成「Node 启动之前要跑的东西」：`.mise.toml` 的 `[env]` 模板在 Node 可用前求值的 bootstrap helper；同一能力只留一份实现，准入判据见 `scripts-and-commands.md`。

依赖边写进根 `package.json` 与消费 workspace 的 `devDependencies`（`workspace:*`）：`pnpm why @greypan/monorepo-kit` 是「谁在消费」的唯一答案。包 `private: true` 不进发布面；它不加入 `.changeset/config.json` 的 `ignore`——门禁行为变更值得留记录，代价是改检查逻辑要写一条带包名的 changeset。

## 后果

- 相对路径深度这一维消失，跨包引用变成稳定 specifier，新增模块不动 `exports`。
- 门禁与编排的测试进入 turbo 图：并行、缓存、按包定位失败。
- 加载面从「按需取一个模块」变成「整包」，配置求值期读表会把整包图带进来；相对 dev/test 启动时间可忽略，因此没做惰性加载。
- 门禁入口多一层 `node_modules` 解析；提交路径本来就经 `pnpm run` 启动，「需要先 install」这个前提不变。
- `scripts/lib/` 的准入判据从三类职责混住收窄成一条纯 bootstrap 约束。

## 替代方案

- **维持现状，只补准入判据**：零迁移成本，但三个问题都留着。
- **只抽仓库无关的纯工具**：解决不了端口表的引用深度与测试归属，而这两件才是驱动决策的问题。
- **并入 `@greypan/test-kit`**：否决。那个包是跨包复用的浏览器测试基建，对消费方一无所知；搬进去会让基础设施包反向依赖本仓库的路径、语料与项目名。
