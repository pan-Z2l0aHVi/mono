# ADR-0012: PR review 结论与人工审查的增量复审

- **Date**: 2026-10-18
- **Revised**: 2026-11-07；2026-11-27，随 [ADR-0026](./0026-lean-agent-context-for-frontier-models.md) 退役 `task-ledger` 并补充 PR 自动跟进、核实修复推送与误判评论闭环。
- **Status**: 已接受

## 背景

本地 hook 只能发现遗漏的检查，不能证明 review 已完成；把 review 放在 PR 阶段，结论覆盖完整变更及验证证据。

## 决策

PR review 由一份绑定 head 的结论承担，不由执行体数量承担：ADR-0021 的自动审查门只读 PR diff 与仓库判据，不听实施者叙述，每个新 head 重跑。reviewed SHA 等于当前 head、`Block` 为 0、required `check` 在当前 head 成功、`coverage.uncovered` 为空，四条同时成立即 review 完成；`uncovered` 非空时结论仍有效、门不变红，但须逐项人工复核收口。task 台账、实施者自查与单独的 `check` 绿灯都不能替代它。

2026-11-07 修订取消「T0/T1 首次 review 必须由独立 reviewer 检查完整 diff」这一固定步骤：门落地后，人与另起会话读同一批字节、按同一份判据、结论同样绑定 head，等待成本却按执行体数量累加。另起一次由 agent 判断，文档不列清单也不禁止；漏检风险没消掉，只是改写进后果。

门给不出覆盖当前 head 的结论时（`error`、`unreviewed`、`stale`、`not_applicable`、fork PR、自动修新 head、只改被剔除路径的产物），PR 上没有 review 结论；`Block > 0` 有结论，处置是修掉发现后在新 head 上重取。人工审查在已有完整结论后按增量复审：以已审 head 为基线，审新 head 的增量、前轮修复及其受影响行为，记录各轮 SHA 与未解决问题；增量不明或旧证据失效时重新完整审查。自动审查每次看完整 diff，不适用增量口径。

## 后果

- 结论必须覆盖当前 base/head；旧 head 的结论不能证明新 head 已通过 review。
- 增量复审减少重复工作，同时保留检查关联行为与重新扩大范围的责任。
- `check` 只提供自动检查证据，不代表 review 结论或发布授权；两条各证一件事，任何一条单独成立都不算。
- 自动审查的射程是滤除生成物后的源码 diff；生成物由 `check-generated` 的 generator 重建证明，不由审查结论证明。
- 省掉的是默认那一次人工细看，押注门坏了会变红而不是被绕开；模型、沙箱档位与后台配置的质量由 ADR-0021「权限拆分与安全不变量」的拓扑断言兜住。
- 独立性改为「结论与实施者叙述隔离」后，只有一个账号也不构成瓶颈：作者不能批准自己的 PR 这条平台约束不变。
- 门没报出的缺陷可能没有任何执行体看过；文档保留人工审查纪律，但不再规定什么时候用它。
