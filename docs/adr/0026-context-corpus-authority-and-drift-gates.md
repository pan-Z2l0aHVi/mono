# ADR-0026: Context 语料权威与漂移门禁

- **Date**: 2026-10-19
- **Status**: 已接受
- **Amends**: [ADR-0004](./0004-progressive-agent-context-architecture.md) 的维护边界——新增语料权威标记与漂移门禁，四层结构与运行时不变量不变
- **Revised**: 2026-10-19 —— 体量棘轮退役；体量只进入只读报表，不再作为门禁
- **Revised**: 2026-10-20 —— 断链与节锚点的检查面从指令面扩到全仓已跟踪 Markdown（研究记录、设计资产、根 README、CHANGELOG、changeset）；链接可点是读取前提，不属于时点性内容。路由、互指、命令存在性仍只判定指令面。同一轮把相对 target 限定为 `./`/`../` 起头（仓库根文档除外），消除「按文件解析」与「按仓库根解析」两种习惯的歧义。解析基线取文档实体路径，`.agents/skills/**` 软链只用于把自撰 skill 纳入指令面；target 按 CommonMark 取 destination，title 与尖括号包裹不参与路径判定
- **Relates to**: 纯文本 `docs/agents/agent-context.md`（语料治理细则）、`docs/agents/workflow.md`（授权机制）

## 背景

指令语料同时被客户端注入与 RAG 按 chunk 检索。结构正确（文件存在、链接可解析）不等于检索正确：外部状态快照、已退役段落和时点性研究都可能以「现行事实」的语气进入上下文。仓库已经删除退役 ADR 文件，但活 ADR 的退役章节、研究文档和流程文档中的规则集状态仍在语料内。

## 决策

1. **权威优先于完整**：同一 concern 只有一个权威；其他位置只写路由或类别句，不复制值。外部状态（ruleset、required context、版本、实现进度）只写权威指针。
2. **chunk 自包含**：授权、前置条件、术语和「非权威参考」标记必须在段内可见。非权威语料用 `<!-- corpus-status: reference -->` 与首段 banner 标记。
3. **退役内容离开活语料**：被取代的决策从活文档删除，历史由 git 承担；不留在正文里靠「已废止」注释区分。
4. **体量只观测**：不按字符数或任何文档体量代理指标设上限，也不维护预算基线。门禁只判断与真实失效模式对应的属性；体量只在 `--report` 中列出，供人工判断。若未来重新引入体量控制，判据必须基于实测成本（token、延迟、检索命中）或单次净增长的 delta，而不是字符数绝对上限。
5. **门禁客观**：只机检已观测漂移或可客观判定的属性——路由完整性、授权指针、快照短语、内容指纹。不做文风或语义质量 linter。

## 后果

- 检索到的 chunk 能自行判断权威性，或至少带出非权威标记。
- 文档同步面从「多份规则集状态」收敛为一个权威指针。
- 路由完整性、授权指针、快照短语与内容指纹由 `check-context` 机检。
- 门禁实现在纯文本 `docs/agents/agent-context.md`；调整判据需修订本 ADR。
- `--report` 只读列出未路由、零入站、缺标记、退役痕迹与最大文档；它不作为门禁，也不设阈值。
- 慢速语料堆积不再有机器门禁，由 R1 的权威优先、R3 的退役清理与 review 承接；报表只提供可见性。
- 代价是新增少量检查；误报通过收缩模式或带注释的 allowlist 处理，不能为通过而放宽判据。
- 语料指纹只证明内容集合与内容变化，不承诺外部索引已重建；索引新鲜度仍由索引侧负责。

## 替代方案

- 继续靠人工 review：已经产生过多次快照复制与退役内容残留，不采用。
- 给每篇文档加完整 frontmatter：渲染与维护成本高于收益；只给非权威语料加最小 HTML 注释标记，不采用全量 frontmatter。
- 建立中心索引文件：索引本身会腐烂，且与 RAG 的按需检索重复，不采用。
- 用字符数预算做棘轮：体量是容量代理而非质量指标，零余量基线会把每次合法新增变成改基线，最终退化为自助放行；不采用。
