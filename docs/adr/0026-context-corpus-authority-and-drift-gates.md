# ADR-0026: Context 语料权威与漂移门禁

- **Date**: 2026-10-19
- **Status**: 已接受
- **Amends**: [ADR-0004](0004-progressive-agent-context-architecture.md) 的维护边界——新增语料权威标记、漂移门禁与体量棘轮，四层结构与运行时不变量不变
- **Relates to**: 纯文本 `docs/agents/agent-context.md`（语料治理细则）、`docs/agents/workflow.md`（授权机制）

## 背景

指令语料同时被客户端注入与 RAG 按 chunk 检索。结构正确（文件存在、链接可解析）不等于检索正确：外部状态快照、已退役段落和时点性研究都可能以「现行事实」的语气进入上下文。仓库已经删除退役 ADR 文件，但活 ADR 的退役章节、研究文档和流程文档中的规则集状态仍在语料内。

## 决策

1. **权威优先于完整**：同一 concern 只有一个权威；其他位置只写路由或类别句，不复制值。外部状态（ruleset、required context、版本、实现进度）只写权威指针。
2. **chunk 自包含**：授权、前置条件、术语和「非权威参考」标记必须在段内可见。非权威语料用 `<!-- corpus-status: reference -->` 与首段 banner 标记。
3. **退役内容离开活语料**：被取代的决策从活文档删除，历史由 git 承担；不留在正文里靠「已废止」注释区分。
4. **预算棘轮**：按非空白字符为每层设上限；清理后下调。上调需要本 ADR 的修订或用户明确例外。
5. **门禁客观**：只机检已观测漂移或可客观判定的属性——路由完整性、授权指针、快照短语、体量预算、内容指纹。不做文风或语义质量 linter。

## 后果

- 检索到的 chunk 能自行判断权威性，或至少带出非权威标记。
- 文档同步面从「多份规则集状态」收敛为一个权威指针。
- 路由完整性、授权指针、快照短语、体量预算与内容指纹由 `ci:validate-context` 机检；密度没有机器基线的问题由体量预算兜住。
- 本 ADR 只确立判据；门禁的具体实现与基线独立落地，落地前不得把本文当作已生效的机检证据。
- 代价是新增少量检查与基线维护；误报通过收缩模式或带注释的 allowlist 处理，不能为通过而放宽判据。
- 语料指纹只证明内容集合与内容变化，不承诺外部索引已重建；索引新鲜度仍由索引侧负责。

## 替代方案

- 继续靠人工 review：已经产生过多次快照复制与退役内容残留，不采用。
- 给每篇文档加完整 frontmatter：渲染与维护成本高于收益；只给非权威语料加最小 HTML 注释标记，不采用全量 frontmatter。
- 建立中心索引文件：索引本身会腐烂，且与 RAG 的按需检索重复，不采用。
