# ADR-0026: Context 语料权威与漂移门禁

- **Date**: 2026-10-19
- **Status**: 已接受
- **Amends**: [ADR-0004](./0004-progressive-agent-context-architecture.md) 的维护边界——新增语料权威标记与漂移门禁，四层结构与运行时不变量不变
- **Revised**: 2026-10-19 —— 体量棘轮退役；体量只进入只读报表，不再作为门禁
- **Revised**: 2026-10-20 —— 断链与节锚点的检查面从指令面扩到全仓已跟踪 Markdown（研究记录、设计资产、根 README、CHANGELOG、changeset）；链接可点是读取前提，不属于时点性内容。路由、互指、命令存在性仍只判定指令面。同一轮把相对 target 限定为 `./`/`../` 起头（仓库根文档除外），消除「按文件解析」与「按仓库根解析」两种习惯的歧义。解析基线取文档实体路径，`.agents/skills/**` 软链只用于把自撰 skill 纳入指令面；target 按 CommonMark 取 destination，title 与尖括号包裹不参与路径判定
- **Revised**: 2026-10-23 —— `check-context` 增加 workflow timeout 授权条款机检，覆盖 CI/workflow timeout、runtime 与 run budget 等上限；验证调整/新增须在实施前取得用户明确授权，并识别例外、待批准期间先改、事后追认或默认授权（包括先改后补授权、自动授权，以及将授权规则或政策声明为不适用），以及允许未先取得用户批准就改动的同义写法。机检还检查为通过失败检查而放宽、遗漏申请值/原上限/run 耗时/log 等证据、未耗尽原上限（包括 run 未触及或未命中旧 cap）或非超时原因仍允许提高、用典型/中位/最快/热缓存运行替代最慢可比运行，以及收紧保护被否定或降为建议（包括缩短上限可停止有效 job）。检查按授权清单的条款结构与概念类别识别并接受同义表述，允许同一授权项中的相关类别与子项要求分句陈述；不做通用措辞或语义质量评分
- **Revised**: 2026-10-23 —— 完善 timeout policy gate：纳入授权清单中未限定到无关操作的通用审批豁免；每个并列执行类别须在相关条款中各自关联到 timeout/wait/retry cap 要求，避免只因同段提及而误判覆盖。
- **Revised**: 2026-10-23 —— timeout 授权判据接受 `subject to explicit prior user authorization` 等等价要求表述；否定的例外禁止（如 “exceptions are not allowed”）不判为豁免。
- **Revised**: 2026-10-23 —— 授权豁免检测不把 “isn't optional” 与 “never optional” 等否定可选性的强制表述判成豁免；收紧限制的保护判据要求明确证明有效工作可继续或完成，不以泛称“保留工作记录”代替。
- **Revised**: 2026-10-23 —— timeout 授权条款关联识别覆盖 `execution budget` 与 `execution-budget` 两种写法；增加明确拒绝以网络、依赖等非超时故障作为提高上限理由的检查。
- **Revised**: 2026-10-23 —— timeout 授权机检把引用“this rule”的紧急豁免、被动语态的批准绕过及未限定操作对象的紧急审批流程绕行纳入冲突判定。
- **Revised**: 2026-10-23 —— timeout 授权机检识别将批准或授权表述为 presumed、assumed、deemed、implicit 或 implied 的默认授权，并区分明确否定此类推定。
- **Revised**: 2026-10-23 —— 无关操作豁免仅限于其所在条款；上限术语先于适用类别的直接范围陈述可通过；明确禁止提前提高上限的句子不作为放宽许可。
- **Revised**: 2026-10-23 —— 通用修改授权与新增授权分别覆盖全部列举类别；独立 retry/wait cap 条款纳入扫描，明确禁止的提前提高不视作许可，timeout increases/raises 也按授权绕行检查。
- **Revised**: 2026-10-23 —— 授权推定的否定只匹配对推定本身的否定，不把“用户未反对”误作否定；收紧保护接受 `doesn't interrupt` 这一等价措辞。
- **Revised**: 2026-10-23 —— 无关操作豁免要求变更对象明确指向发布、部署或合并等操作，不因条款仅在这些操作期间生效而豁免；收紧保护按分句关联允许中断与拒绝中断，避免一方被另一方掩盖。
- **Revised**: 2026-10-23 —— 最慢可比运行判据拒绝将其降为不一定、并非总是或无需采用的可选依据。
- **Revised**: 2026-10-23 —— 最快或缓存热运行的禁止性表述接受 `may not` 与 `shall not` 等价写法，不把否定情态中的 `may` 误判为许可。
- **Relates to**: 纯文本 `docs/agents/agent-context.md`（语料治理细则）、`docs/agents/workflow.md`（授权机制）

## 背景

指令语料同时被客户端注入与 RAG 按 chunk 检索。结构正确（文件存在、链接可解析）不等于检索正确：外部状态快照、已退役段落和时点性研究都可能以「现行事实」的语气进入上下文。仓库已经删除退役 ADR 文件，但活 ADR 的退役章节、研究文档和流程文档中的规则集状态仍在语料内。

## 决策

1. **权威优先于完整**：同一 concern 只有一个权威；其他位置只写路由或类别句，不复制值。外部状态（ruleset、required context、版本、实现进度）只写权威指针。
2. **chunk 自包含**：授权、前置条件、术语和「非权威参考」标记必须在段内可见。非权威语料用 `<!-- corpus-status: reference -->` 与首段 banner 标记。
3. **退役内容离开活语料**：被取代的决策从活文档删除，历史由 git 承担；不留在正文里靠「已废止」注释区分。
4. **体量只观测**：不按字符数或任何文档体量代理指标设上限，也不维护预算基线。门禁只判断与真实失效模式对应的属性；体量只在 `--report` 中列出，供人工判断。若未来重新引入体量控制，判据必须基于实测成本（token、延迟、检索命中）或单次净增长的 delta，而不是字符数绝对上限。
5. **门禁客观**：只机检已观测漂移或可客观判定的属性——路由完整性、授权指针、快照短语、内容指纹，以及 workflow timeout 授权条款的适用范围、用户事先授权、申请证据、原上限耗尽与失败原因、最慢可比运行评估、收紧限制时的证据和有效工作保护。机检识别免授权、审批待定/事后追认、失败后为通过检查而放宽、缺少必要证据、用其他原因解释仍允许提高、以典型/中位/最快/热缓存运行替代最慢可比运行，以及保护要求被否定或弱化等矛盾。检查范围按授权清单的相关条款结构识别，包括单独成项的 runtime/deadline、收紧限制、指代 timeout 调整的授权条款，以及引用前述授权要求或紧急情形的间接豁免条款。机检按概念类别判定并接受同义表述；不做通用文风或语义质量 linter。

## 后果

- 检索到的 chunk 能自行判断权威性，或至少带出非权威标记。
- 文档同步面从「多份规则集状态」收敛为一个权威指针。
- 路由完整性、授权指针、快照短语、内容指纹与 timeout 授权条款要点由 `check-context` 机检。
- 门禁规则说明由 `docs/agents/agent-context.md` 承载；timeout 授权政策由 `docs/agents/workflow.md` 承载；可执行检查实现在 `scripts/lib/context-corpus.mjs` 与 `scripts/lib/context-invariants.mjs`。调整判据需修订本 ADR。
- `--report` 只读列出未路由、零入站、缺标记、退役痕迹与最大文档；它不作为门禁，也不设阈值。
- 慢速语料堆积不再有机器门禁，由 R1 的权威优先、R3 的退役清理与 review 承接；报表只提供可见性。
- 代价是新增少量检查；误报通过收缩模式或带注释的 allowlist 处理，不能为通过而放宽判据。
- 语料指纹只证明内容集合与内容变化，不承诺外部索引已重建；索引新鲜度仍由索引侧负责。

## 替代方案

- 继续靠人工 review：已经产生过多次快照复制与退役内容残留，不采用。
- 给每篇文档加完整 frontmatter：渲染与维护成本高于收益；只给非权威语料加最小 HTML 注释标记，不采用全量 frontmatter。
- 建立中心索引文件：索引本身会腐烂，且与 RAG 的按需检索重复，不采用。
- 用字符数预算做棘轮：体量是容量代理而非质量指标，零余量基线会把每次合法新增变成改基线，最终退化为自助放行；不采用。
