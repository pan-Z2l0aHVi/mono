# ADR-0026: Interweave 标准化标签名称与自动复用

- **Date**: 2026-08-16
- **Status**: 已接受

## 背景

语义标签需要被全局复用，才能让 Resource—Tag 归属和 Map 聚合保持清晰。若用户能创建标准名称完全相同的多个标签，UI 无法有效区分它们，资源关系也会无意义地分散。与此同时，v1 不采用标签别名、自动语义合并或复杂标签治理。

## 决策

v1 在创建标签前对用户输入执行确定性的名称标准化，并只保存标准化后的标签名称；不另设持久化 `normalized_key`。若标准化后的名称已经存在，App 必须自动复用既有标签，不创建新的标签记录。

标签不支持别名。标准名称不同的标签即使语义相近，仍是不同标签；v1 不提供底层标签合并逻辑，用户可自行删除旧标签并为受影响 Resource 添加目标标签。标签名称的标准化规则确定为：

1. 去除首尾空白（含普通空格与 Unicode 空白）；
2. 将连续的多个内部空白折叠为单个空格；
3. 执行 Unicode NFC 规范化；
4. 标准化后为空字符串则拒绝；
5. 保留用户输入的原始大小写（如 `iOS` 与 `ios` 保持各自原样）；
6. 不自动剥除 `#`、标点或连字符；
7. 不包含翻译、同义词判断或其他自动语义归并。

## 后果

- 本地资源库必须以原子方式保证标准名称的唯一性，使并发创建也只能得到一个既有或新建的标签。
- 创建标签的“新建”分支仅适用于没有同名标准标签的输入；精确同名时直接返回既有标签。
- 标签建议主要帮助用户选择不同但相近的既有名称，不能暗示系统已建立同义关系。
- Map 仍只从精确的 Resource—Tag 归属派生；不因近似名称产生隐藏关联。
