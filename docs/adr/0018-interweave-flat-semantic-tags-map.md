# ADR-0018: Interweave 扁平语义标签与派生 Map

- **Date**: 2026-08-15
- **Status**: 已接受

## 背景

Interweave 需要让用户理解资源之间的联系，但不能复制文件树、要求用户维护复杂知识图谱，或让格式与状态信息污染关系视图。产品将 Map 作为资源关系发现能力，而非装饰性全量图谱。

## 决策

1. 标签是扁平、可复用的**语义标签**。不存在父子层级、路径、继承、标签间显式关系或用户维护的直接 Resource—Resource 关系。
2. Resource 之间的关联仅由共享语义标签派生。Map 必须能解释任意关系的依据：相关 Resource 共享了哪些标签。
3. 文件/来源类型、来源可用状态、最近添加时间等属于系统元数据，不是语义标签，不进入 Map。
4. Map 采用分层探索：全局先展示标签共现形成的主题群，并突出强关联；用户聚焦标签后再展开直接关联的 Resource 与可继续探索的其他标签。
5. 未标记 Resource 不混入 Map 网络，而以独立的未连接资源入口或数量提示呈现。
6. Map 以探索和轻量纠正为主：允许打开 Resource、查看关系依据、打开 Source、修改单个 Resource 的标签；不提供手工连线、拖拽排版、批量画布整理或复杂条件构建。

## 后果

- 用户只需维护 Resource—Tag 归属，主题结构和跨主题桥梁由资源积累自然产生。
- Map 可以帮助发现关系、孤立资源和标签质量问题，但不承担目录、数据库查询器或知识图谱编辑器职责。
- 高度泛化的标签与偶发共现不应在全局视图中制造噪音；弱关联只在局部探索中按需展示。
- 后续若引入新的关系类型，必须先重新评估本 ADR，因为它会改变 Map 的可解释性与用户心智。
