# ADR-0025: Interweave 重复 Source 由用户自行管理

- **Date**: 2026-08-16
- **Status**: 已接受

## 背景

将相同路径或 URL 视为全库唯一 Source，要求用户在添加时理解“已有 Resource”的定位结果，并会让一键替换等直接操作遇到额外冲突。v1 优先降低纳入时的心智负担：用户应能将每次主动添加都作为独立 Resource 或独立 Source 保留下来。

## 决策

v1 全面取消 Source 的全局去重与重复干预。无论是新建 Resource、为已有 Resource 新增 Source，还是一键替换 Source，只要用户发起添加或替换，即使文件路径或 URL 与任一既有 Source 完全相同，也照常执行该操作；App 不定位既有 Resource、不拒绝、不合并、不转移 Source，也不跳过 URL 的初次抓取。

文件路径和 URL 仍按各自输入规则校验、清理并保存，但不生成具有唯一约束的全局 `source_key`。同一外部入口可被多个 Resource 或同一 Resource 的多个 Source 引用，是否整理由用户自行决定。

未来可以另行评估低优先级的、用户主动触发的一键重复扫描能力；它不属于 v1，且不得反向改变本 ADR 的“添加时零干预”规则，除非通过新的产品决策与 ADR 明确设计。

## 后果

- Resource/Source 写模型不建立全局 Source 唯一约束，重复添加始终返回本次新建或替换的结果。
- URL 初次添加即使与既有 URL 完全相同，也必须按 ADR-0022 进行本次抓取，并独立写入可用性与展示元数据。
- ADR-0021 中关于全局 `source_key`、重复定位与重复请求跳过的决策被本 ADR 取代；其中的输入规范化和“重定向不改写初始 URL”的规则由后续实现按需保留，但不再用于去重。
