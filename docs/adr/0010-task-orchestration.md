# ADR-0010: 需求拆分与 task 派交编排层

- **Date**: 2026-10-03
- **Status**: 已接受

## 背景

需求拆分、并行度、worktree 分配和跟进依赖执行环境与可用资源。仓库内的固定派发规则无法可靠反映外部调度的实际状态，也会把编排工具的生命周期耦合到项目文档。

## 决策

需求拆分与 task 派发由外部编排层承担。仓库定义 task 归属、worktree、review 与交付的不变量，但不规定编排层的角色拓扑或派发方式。task 分级依据改动的影响，不依据编排形态；现行判据由 task-ledger skill 维护。

一个可变 task 只有一个实施 worktree 和 owner。独立 review 的要求由仓库 review 流程定义，编排层负责提供适合其环境的执行方式。

## 后果

- 仓库可与不同的编排工具协作，无需复制调度状态或角色协议。
- 外部编排层负责协调 task 与 worktree；本地台账只记录归属和进度，不代替调度或 review。
- 仓库边界与具体执行环境的衔接需要由编排层保证。

## 替代方案

在仓库内固定拆分规则和角色拓扑可以支持统一的离线派发，但会使规则与实际调度脱节，因此不采用。
