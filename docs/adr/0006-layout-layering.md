# Layout layering for local overlays

`web-ui-layout` owns the stacking order of its sibling regions: base content and sidebar are below the sticky header. This preserves interaction with non-portal overlays rendered inside header components when narrow viewports make them overflow their grid area. We retain local overlays by default rather than forcing Portal usage. Portal overlays use a separate semantic order: anchored portal overlays and menus, then Toast, then loading overlays; submenus are above their parent menu, while native Dialog and Drawer remain in the browser top layer. Select, Popover, and Tooltip join the menu layer only when their `portal` property is enabled. An explicit `overlayContainer` uses these values but its caller owns any ancestor stacking context; the library does not modify that ancestor or inject parent styles. BackTop is an application auxiliary layer, above base content and below portal menus.
