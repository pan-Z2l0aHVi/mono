# pi-rex-orchestrator

- 私有 Pi 扩展，由 Pi 的 jiti 直接加载 [`src/index.ts`](./src/index.ts)，不经 Vite 打包；`src/` 里不能出现只有构建期才注入的东西（`import.meta.env` 等）。零运行时外部依赖：只用 Node 内置模块与 Pi 扩展 API，**不要**引入 `workspace:*` 运行时依赖或第三方运行时包。
- Pi 宿主 API 的类型声明在本包的 [`src/pi-types.ts`](./src/pi-types.ts)，不装 `@earendil-works/pi-coding-agent`（进 devDependencies 会拖入整个 provider 闭包并需要改根 `pnpm-workspace.yaml` 的 `allowBuilds`）。声明对照过 `1.5.2` 真实宿主；升级 Pi 后先对照 `dist/core/extensions/types.d.ts` 再改。
- 激活只看环境变量（`REX_SESSION` 且 `PI_REX_ORCH !== "0"`）。派生命令的 `/usr/bin/env PI_REX_ORCH=0` 前缀是防递归硬约束：`rex run` 不支持 `--env`，在 `pi.exec` 里传 env 到不了子 PTY，绕过前缀会让「把 pi 配成 worker」递归成为操作者 + agent 协调者。
- `rex_cli` 是模型操作 Rex 的唯一出口；直接 `rex_cli` 只做只读或不动仓库代码的操作，`rex run` 不是改码通道，仓库代码改动一律走 `rex_spawn_agent`。Rex 操作是本扩展唯一放行的写入口：所有参数以 argv 数组注入 `exec`。先跳过 `rex --help` 里的前置全局 flag 找到实际子命令；支持等号值形式、重复 `-v` 与 `-S`/`-C` attached 值。未知 flag、缺值、前置 `--` 或只有 flag 时 fail closed，仅保留 `-h` / `--help` / `--version` 作为根自查，且允许无值全局 flag 位于根自查之前。session 只对 2026-11-21 真机 `--help` 派生的**自动注入清单**注入，插在 `--` 前；没有 `--` 时追加到 argv 末尾，非清单命令原样透传。该清单是注入策略而非 Rex CLI 事实全集：`run`、`split`、`do`、`send`、`send-key`、`capture`、`focus`、`zoom`、`move`、`swap`、`wait`、`block ls/list/inspect/focus/send/send-key/capture/zoom/move/swap/call/rename/close`、`window new/ls/list/inspect/focus/move/rename/close`、`client ls/list`、`api call`、`forward|fwd new/open/share/ls/list/close`。升级 Rex 后重枚举 help 并同步测试。拒绝点：拒绝长驻 `events`；`rejectsWorkerAgent` 只静态检查 `do` 以及 `new -- ...`、`run -- ...`、`split -- ...`、`window new -- ...` 的命令段，不覆盖 `send` / `send-key` / `block call ... write` 的文本和 `bash -lc '...'` 等 shell 包装，prompt 硬性禁止借这些通道绕过路由。启动内置 `claude` / `codex` / `pi` 或已解析 profile 的 binary basename（来自 `rex-orchestrator.json`）必须走 `rex_spawn_agent` 的 worker 生命周期；进程匹配按 basename，同 basename 的不同 profile 会一并拦截。输出先保留 stdout，再附 stderr 与退出码；stdout 取前 200 行或 16000 字符的较早边界，行截断与字符截断分别标注。非零退出的 stderr 只留末尾 2000 字符。`wait` 与事件型 `do` 共用 15s 默认超时，超时会返回 `[killed]`；长等待改用心跳式 `capture` 轮询。
- `rex_cli` 的文件写护栏独立于 Rex 路由：`guard.ts` 继续硬拦 `bash` / `write` / `edit` / `powershell` 与 `destructiveHint` MCP 工具，也不为普通 Rex 操作增加确认闸门；命令注入、拒绝点、超时和输出边界以上一条 `rex_cli` 契约为准。
- 护栏两层缺一不可：`session_start` 挂 `setActiveTools` 白名单（声明可能滞后一轮），`tool_call` 钩子硬拦 `bash`/`write`/`edit`/`powershell` 与 `destructiveHint` MCP 工具兜底。本协调者**有意**摘掉 `bash`：git 与探查全部走专用工具（内部经 `pi.exec`），模型层面保留 shell 是多余攻击面。退出与 `session_shutdown` 都要还原工具集，否则 `/reload` 后工具永久消失。
- 阶段 1 实测锁定的 CLI 事实（改模板前先重测，不要凭记忆）：claude 的位置参数 prompt 必须放在值型 flag（`--add-dir`）之前，否则被吞成 flag 值；`codex exec resume` 没有 `--add-dir` 且 `--json` 跟在 resume 之后；claude 的 OSC 7501 上报已实测，codex 未验证按 `supportsOsc7501: false` 处理（Send-ACK 强校验自动跳过）。
- `rex events` 的双层 JSON Schema 与 `rex block ls`/`rex run --json` 形状来自 2026-11-19 真机抓包（rex 0.1.0-preview.21），期望值钉在 [`src/__tests__/rex-events.spec.ts`](./src/__tests__/rex-events.spec.ts)；没实测到的 `program_status_changed` 按设计文档形态解析并保持「不认识就当作没有」。
- Pi session id 在工厂期拿不到：交接区（`HandoffStore`）延迟到 `session_start` 用 `ctx.sessionManager.getSessionId()` 创建，工具执行前 `requireStore()` 兜底。改这个时序前先读 [`src/orchestrator.ts`](./src/orchestrator.ts) 的 `session_start` 处理。
- interactive 投递的 Send-ACK 监听必须在 `rex send` **之前**订阅，且投递只记 turn 不做合成状态转移（`markTurnDispatched(..., { notifyTransition: false })`）：自家转移会抢先触发 ACK，把「未送达」永远误判成「已确认」。
- headless 续跑走 `replaceBlock` 原子替换：旧 Block 移入 `retiredBlockIds`，其 `block_closed` 事件不算异常；一个逻辑 worker 至多一个活跃 Tab。续跑需要的 agent session id 从该轮 `events.jsonl` 尾部提取，提取不到就报错让人工 inspect，不要静默起新会话。
- `scripts/run-headless.mjs` 是纯 JS（不经 jiti/TS），改它时保持只用 Node 内置模块；放在 `scripts/` 而非 `bin/` 是因为根 `.gitignore` 把 `bin/` 当构建产物目录排除。子进程 `close` 里真实退出码优先于信号合成码；`eventsStream.end()` 的 flush 回调之前不得 `process.exit`，否则截断末尾 JSONL 丢 `session_id`。契约由 [`src/__tests__/run-headless.spec.ts`](./src/__tests__/run-headless.spec.ts) 的假 CLI 钉住。
- worktree 清理是保守契约：`git status --porcelain` 为空后，依次判祖先链、`<baseRef>` 内容落地，再处理未落地 / 无法判定；squash 由逐路径内容比对识别。内容探针先解析并钉住 `<baseRef>` 对应的 `<baseSha>`，再钉住 `refs/heads/<branch>` 的 tip；`baseRef` 只用于展示，不得作为比较对象。取 merge-base 后用 `--name-only -z --no-relative --no-renames` 列出仓库根相对的改动路径，让重命名的删除侧与新增侧分别进入后续比较；路径无法从 UTF-8 字符串无损往返时整体返回 `inconclusive`。每条 `git diff --quiet --no-relative <baseSha> <tip> -- :(top,literal)<path>` 返回 0 后，还必须用同一 pathspec 在 tip 或删除侧 merge-base 上由 `git ls-tree -r -z <rev> -- :(top,literal)<path>` 找到对象；空匹配返回 `inconclusive`。路径列表、对象校验与每条 `--quiet` 都必须完整结束且 `killed` / `truncated` 均为 false，变更路径超过 200 条直接按 `inconclusive` 处理。探针只读 Git 引用，不读取主仓工作树或 ambient index。内容落地分支只能以探针旧 tip 执行 `git update-ref -d refs/heads/<branch> <tip>`；删除前必须完整读取 `git worktree list --porcelain`，任一 worktree 仍检出该 ref 时保留并说明路径，查询失败同样保留，绝不退化为 `-D`。探针后分支已消失按清理完成，tip 变化或原子删除失败时保留分支并重判，绝不升级为 `-D`。祖先链仍走 `branch -d`，显式 `force` 才走 `branch -D`。内容未确认时优先走仓库自身 PR 流程；仅无 PR 流程仓库可在用户确认后本地 `git merge --no-ff`。判定所需命令失败时按 `inconclusive` 保留并给出诊断；未提交改动优先级最高。零提交仓库（无 HEAD）屏蔽 worktree 选项。测试用真实 `git init` / `git worktree add` 建仓（[`git-inspector.spec.ts`](./src/__tests__/git-inspector.spec.ts)），手写 fixture 会掩盖 linked worktree 的 `gitdir:` 布局差异。
- 联调软链用包脚本 `pnpm --filter @greypan/pi-rex-orchestrator run link:pi`；删开发 worktree 前必须 `link:pi -- --main` 切回主仓库 main 常驻路径，防止软链悬空。真实 worker 派生的端到端联调在临时沙箱仓库做，不要拿主力 monorepo 做破坏性联调。
- worker 跟踪按 Pi session 持久化在交接区的 `registry.json`（0700 目录内，原子写）：`/reload` 或会话恢复后由 `session_start` 重建注册表再全量对账，`rex_list_workers` / `/rex-status` / `/rex-cleanup` 不会丢 worker。改注册表字段时同步 `WorkerEntry` 的持久化/恢复两侧，恢复按「不认识就当作没有」校验形状。
- 验收用 `git status --porcelain -z --untracked-files=all` 逐文件记账：默认 porcelain 会把新目录折叠成 `?? dir/`，预览读目录会 EISDIR 且基线对比失真。worktree 检出起点钉在派发时的 `base_commit`，不跟随建 worktree 时的当前 `HEAD`。
- pi 会话结束（quit / reload / print 模式跑完）后扩展 runtime 整体失效，`pi.sendMessage` / `setActiveTools` 在 stale runtime 上直接抛异常：聚合计时器与事件环必须在 `session_shutdown` 停摆，任何延后触发的回调先检查 `active`。这个坑由真实 E2E 揭示（宿主进程带未捕获异常退出），两个回归测试钉在 `orchestrator.spec.ts`。
- 在 claude-code 会话的 shell 里调 `pi` 做 E2E 前先清掉 `ANTHROPIC_AUTH_TOKEN` / `ANTHROPIC_BASE_URL` / `ANTHROPIC_API_KEY`：pi 会把它们当自己的 Anthropic 凭证与网关用，请求会被网关以 403 拒掉；用户自己终端里没有这些变量，所以「我这里 403、用户能跑」先查环境再怀疑代码。
- 两个由独立 review 揭示、直觉上容易「优化」错的坑：① OSC 状态记录会因断连对账重放，只按 `updated_at` 单调（`<=` 即拒）+ error 按轮次（`errorTurn`）计数才防得住重复计数误熔断，按「进入 error 就 +1」会被重放骗到；② 全新 worktree 的分支没有独立提交，`git branch --merged` 视其为已合并——对派生结果不明（`unconfirmed:` placeholder）的 worktree 做非 force 清理会命中 clean+merged 判定、误删可能正被使用的 worktree，必须先过用户确认。
- worker 按各自 cwd 加载所在目标仓库的 agent 规范（Claude Code 2.1.283+ 与 Codex 均原生支持 `AGENTS.md`，外部目标仓库仍可能使用 `CLAUDE.md`，Claude 另读 `.claude/`；本仓禁根 `CLAUDE.md` 并以 `.claude/{rules,skills}` POSIX 软链对齐）：共享目录天然生效；worktree 只带**被跟踪的**配置，被 ignore 的本地配置（`.claude/settings.local.json` 已进 `scanIgnoredDeps` 默认候选）缺失时靠 brief 告知，brief 同时要求 worker 开工前先读仓库级规范（与 [`src/orchestrator.ts`](./src/orchestrator.ts) 保持多目标仓库通用语义）。扩这个边界时同步 `scanIgnoredDeps` 默认候选与 brief 文案。
