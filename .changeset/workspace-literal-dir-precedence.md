Two changes to workspace scanning. First, `defineWorkspaceDepBoundaries` no longer treats a literal workspace directory's own `dist`/`build`/`coverage`/`__tests__` subdirectories as workspaces: the artifact-name skip now starts from whether the scanned root is itself a package, so build output under a literal workspace stays out of the dependency graph. Containers keep scanning those names at their first level, where such directories are real packages. Second, `readPnpmWorkspaceDirectories` now documents that it returns container and literal directories without distinguishing them, and that consumers decide by the presence of `package.json`: the boundary check stops descending into artifact-named subdirectories of a package, while the corpus and link checks collect only a package's root-level entry document and README. A container directory that itself carries a `package.json` is therefore treated as a package and silently loses those children; that layout is not supported.
