Internal change: no published package is affected. Formatting coverage and the T2 fast path in `pnpm task` are decoupled, so a quick change no longer has to pass through the task machinery to end up formatted.

- `.agents/checks/format-clean` is a new commit-boundary check that verifies instead of rewrites: it takes the staged list from `git diff --cached --diff-filter=ACMR` and hands the **working-tree copies** of those paths to `vp check`, `stylelint` and `gofmt -l`, with no fix flag in any of the three invocations (the `AGENT_*_CMD` entry overrides exist for the test fixture and are treated as trusted input, as the script header states). "Not clean" is deliberately broader than "not formatted", because `vp check` judges formatting, lint and types in one pass — the failure message therefore points at `vp check`'s own output rather than promising that a fixer will clear it. A fixer running at commit time would break the freeze invariant it is meant to protect, and `vp staged`-style tools reach for a stash to handle partial staging, which drags other people's in-progress work into the commit — the two reasons that pipeline was retired. The escapes from that promise are closed fail-closed rather than papered over with `--`: a staged path starting with `-` is rejected instead of being passed to a tool that would read it as an option (a file literally named `--fix` at the repo root would otherwise turn the check that promises never to rewrite into a rewrite), a path git C-quotes (a name containing `"`, a backslash or a newline, which `core.quotePath=false` does not un-escape) is rejected because the bytes handed over would name a file that does not exist, and a non-zero `gofmt` exit is reported rather than swallowed by `set -e`, so a not-clean verdict always names what to run (the branches that refuse to judge at all — Git cannot list the index, a tool will not start, a staged path is `-`-prefixed or git-quoted — name the blocker instead, because no fixer would clear it). Glob metacharacters, which git does not quote, stay a documented residual — this repo tracks `apps/vue-web-ui-demo/src/pages/[...all]/index.vue`, so refusing them would block legitimate paths to catch a malformed name. Each tool is probed with `--help` before it is used, so a worktree without installed dependencies reports "the check cannot run" rather than blaming the author's formatting.
- `guard` no longer returns early when a worktree has no active task: it now runs the checks listed in `scripts/task.mjs`'s `alwaysOnChecks` first. `format-clean` is on that list and `changeset-required` deliberately is not — a commit with no task has nothing to attribute a changeset to, so requiring one would only buy an empty shell. Registration is opt-in, which means a new check missing from the list costs a guarantee rather than blocking legitimate commits. Registered entries are then checked for coverage: checks mount on "regular file plus executable bit", so a `format-clean` that lost `+x` would have kept passing commits while doing nothing, and the no-task path now aborts and names it instead. The one bypass this does not close is deleting the whole `.agents/checks/` directory locally without committing it — a missing directory gives the kernel nothing to mount, so on that path the guarantee is held by the directory being under version control rather than by the check itself; the boundary is documented instead of hidden. A second bypass has the same shape: pointing an `AGENT_*_CMD` entry override at a program that always succeeds. The coverage probe asks whether a registered check ran, not whether it still judges anything, so an emptied check is indistinguishable from a passing one in `guard`'s output — `docs/agents/commit.md` now names that env override in its list of prohibited bypasses rather than leaving it as a documented test seam only. All three commit paths carry the same formatting guarantee: T0/T1 get it from `freeze`'s normalization plus this check, T2 and untasked commits get it from this check alone — including the one commit CI makes, the version PR, which reaches the same check provided its commit runs hooks at all (`workflow.md` keeps the reasoning as inference rather than a measured CI run: for an npm-package bump the staged set is `CHANGELOG.md` — in vp's format ignore —, canonical-shaped `package.json` and deleted changeset files, which `--diff-filter=ACMR` does not list, while a bump of the non-ignored `@greypan/interweave` would additionally stage generated files this check can judge, and the mise/pnpm/wails3 chain in that job sits in front of the check either way). One kernel-side fix serves every check rather than just this one: a failing check now reports both of its output streams. Checks run with `stdio: 'pipe'`, so nothing reaches the terminal on its own, and the `detail` used to keep only stderr — which for a tool like `vp check` means the file list and the reason were thrown away and the author saw a single trailing error line.
- The check reads working-tree content while `changeset-required` reads staged blobs. That split is intentional and documented: the kernel's own snapshot hashes working-tree bytes (`currentSnapshot`), so an index/worktree divergence surfaces as "fix it and re-add" instead of two gates disagreeing about which copy is real. `.changeset/root-pr137-selfcheck-gaps-260920.md` is still unconsumed and will land in the same CHANGELOG, so its "both boundaries read the index" sentence is now scoped to `changeset-required`, and its clean-worktree sentence names the T2 exemption.
- `new` and `start` stop requiring a clean worktree for T2. The requirement exists because `freeze` stages the whole worktree with `git add -A`; T2's fast path never reaches `freeze`, so it was paying an isolation cost for a risk it does not carry. The exemption stops at `start`: a T2 that asks for `freeze` anyway (the only reason being to record verification, which requires a frozen phase) must have a clean worktree, since `git add -A` would otherwise sweep other people's in-progress files into the snapshot and out through the commit. What T2 gives up in exchange is a diff boundary — its commit is whatever the index held — which `workflow.md` and ADR-0014 now state as the level's contract: anything meant to be reviewed as a unit or reverted as a unit belongs at T1 or above.
- `scripts/task.test.mjs` covers the wiring rather than oxfmt's opinion: the gate runs on the no-task path and blocks a commit, `changeset-required` does not run on that path even while installed, both run for T2, `format-clean` runs again at `freeze`, a lost `+x` on the always-on check aborts the no-task guard, and neither a `-`-prefixed nor a git-quoted staged path ever reaches a formatter — both probes assert that the formatter was never invoked at all rather than looking for a line that could not appear. The staged list reaches each tool as one argument per path (a `demo 目录/a b.mjs` name stays intact, an untracked file is never checked, only `.css/.scss/.less/.html/.vue` reach stylelint and only `.go` reaches the `gofmt -l` branch, which signals through stdout rather than its exit code); the load-bearing pair there is a full-line positive match plus a count of the recorded calls, since the stub only logs paths that exist on disk and a whitespace-split argument would drop the count while leaving no negative line to assert on. A failing check's report survives into the guard message: the stub writes its finding to stdout, which is where the kernel used to leave nothing behind. T2's freeze rule is pinned from both sides: refused with foreign work in progress, allowed from a clean start. The fixture overrides the tool entry points through `AGENT_VP_CMD` / `AGENT_STYLELINT_CMD` / `AGENT_GOFMT_CMD` because it has no `node_modules`.
- `docs/agents/workflow.md`, `docs/agents/commit.md`, `docs/agents/linting.md`, `docs/agents/build.md`, `.agents/rules/commit.md`, ADR-0014 and ADR-0001 carry the updated contract; `docs/agents/build.md`, `docs/adr/0001-ci-pipeline.md` and the sibling changeset named above are corrected where their wording had become narrower than the kernel.
