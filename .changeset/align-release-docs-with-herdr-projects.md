Internal change: aligns the release documentation with the herdr-projects orchestration layer. `docs/agents/release.md` drops the orchestration-layer responsibilities and the dangling `Manager` reference left by `6d7e1694`, and states two facts that shape the remaining flow: `ci.yml` only runs on PRs whose base is `main`, so the release-lane PR is what carries integration verification and the merge gate; and the release lane keeps each task's own commit while the lane-to-`main` merge stays squash, because squashing inside the lane destroys the per-task boundary the task evidence chain is built on. `docs/agents/workflow.md` no longer describes the release playbook as aggregating approved tasks under an aggregating T0 task; it now points at ADR-0022 and derives the integration PR's level from the tasks it carries. Adds ADR-0022 recording that shape: release-lane ownership, why `ci.yml`'s trigger list is deliberately left as-is, the merge strategy on each side of the lane, and the accepted cost that a task PR based off a non-`main` branch has no CI of its own before it enters the lane.
