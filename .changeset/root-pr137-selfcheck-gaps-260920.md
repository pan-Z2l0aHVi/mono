Internal change: no published package is affected. `pnpm task` gets stricter where the PR #137 review found a gate that was asserted in the docs but not enforced by the kernel.

- `verify` no longer defaults to `--result pass`. The command records evidence and executes nothing, so a recorded verdict must be stated by whoever ran the checks.
- `approve` validates the approver id with the same `[A-Za-z0-9][A-Za-z0-9._-]{3,39}` shape `review` already required, and rejects an approver who reviewed that same diff. An explicit `--owner` (or `AGENT_TASK_OWNER`) is validated by that same shape in `new` and `assign`, because all four identity fields are compared with each other as strings — the login-name fallback stays unrestricted. Every one of them is also required to be a string: a flag left without a value parses to the boolean `true`, which `RegExp.test` coerces into the four-character `"true"` and accepts, letting a single identity hide as `true` in one field and `'true'` in another. Both `review` and `approve` now compare against the task's owner **history** rather than its current value: `assign` has no phase restriction, so checking only the present field could be walked around by handing the ownership off and then approving as the original owner. The ids stay self-asserted — the kernel prevents misuse, not collusion.
- `drop` requires `--by <agent-id>` and a `--reason` of at least 10 non-space characters, and resolves the task and its phase before complaining about either argument. Re-freezing can also void frozen evidence but leaves the task usable, while `dropped` is terminal, so the event has to name who did it and say enough for a later reader.
- `start` refuses a worktree with uncommitted changes for T0/T1 — T2's exemption arrived later, in `root-format-gate-t2-fastpath-260921`, which is also where a dirty T2 gets refused at `freeze` — and both it and `new` now list the offending paths instead of just reporting that the worktree is dirty. `freeze` stages the whole worktree via `git add -A`, so the cleanliness check that already ran at `new` now runs again where implementation actually begins — a stray file left behind between `new` and `start` can no longer be absorbed into the task's snapshot. Only the `open → active` transition is checked; re-entering `active` after a failing review is not.
- Every check under `.agents/checks/` runs at both task-bearing boundaries: before the freeze snapshot and again inside `guard` before a commit is allowed, with the ran list echoed in the output. The no-task commit path runs only the subset registered in `scripts/task.mjs`'s `alwaysOnChecks` (see `root-format-gate-t2-fastpath-260921`). This is what makes the "no exemption for any level" claim in `release.md` and ADR-0014 true, since a T2 task rarely freezes at all. Which copy a boundary reads is per-check rather than a property of the boundary: `changeset-required` reads the index, file list and content alike, which is what a freeze records and what a commit writes, while `format-clean` — added later in this same release — judges working-tree copies and says so. `docs/agents/workflow.md` no longer says a T2 commit needs nothing but an active task.
- `changeset-required` reads content instead of just filenames. A changeset must open the file with a paired `---` frontmatter block, and one whose frontmatter declares package bumps must also carry a summary — the version PR would otherwise write an empty line into a public package's CHANGELOG. Package lines are recognised with or without indentation, with the value quoted and with a trailing comment, because the frontmatter is YAML and every one of those shapes produces a release — a rule matching only the `key: patch` end-of-line literal would let the others declare a bump while dodging the summary requirement. Detection stays a line-shape heuristic rather than a YAML parser: a version type written so that no single line carries `: …patch…` is out of scope, and the heuristic errs toward counting an extra line, which only demands a summary. The set of files that can satisfy the rule mirrors what `@changesets/read` actually consumes: `.changeset` top level plus `pre/`, names not starting with `.`, and not `README.md` (any case), `AGENTS.md`, `CLAUDE.md` or `GEMINI.md` — that ignore table is case-sensitive apart from `README.md`, so a lowercase `.changeset/claude.md` is a real declaration and is held to the content rules rather than filtered out. None of the ignored names ships a version, so none of them should be able to stand in for a declaration. Requiring the frontmatter to open the file is deliberately stricter than the parser, whose regex is unanchored and would read a setext-heading-prefixed file just fine. The two-line empty shell stays legal: `docs/agents/commit.md` documents it as the "no version impact" declaration. File names are read without shell word splitting and with `core.quotePath=false`, so paths containing spaces or non-ASCII characters are validated instead of erroring out or being dropped; a name containing a newline is still out of scope. An unresolvable base — the history was rewritten under the task — now says the check cannot run instead of reporting a missing changeset, because POSIX sh has no `pipefail` and the pipeline's `|| true` would otherwise swallow Git's failure into the empty list. `docs/agents/commit.md` also stops claiming that CI catches a missing changeset — `changeset status --since` only fails when a changed package needs a version.
- `guard` with no active task reports `task gate: not enforced` on stderr together with the `pnpm task new` entry point, instead of passing silently — "this repo has no gate" and "someone forgot the task" used to look identical. `--` now only terminates option parsing; the trailing values went into a `commandArgs` field that no code ever read.
- `scripts/task.test.mjs` covers each rule positively and negatively: commit-boundary checks on both the T2 and the approved T0/T1 path, the executable-bit filter, the changeset content rules (each malformed shape asserted with its own message tail, because the two share a prefix and a prefix-only assertion leaves one branch unpinned; indented, quoted and trailing-commented package lines, spaced and non-ASCII file names, index-vs-worktree content in both directions, and an unstaged changeset), which names can satisfy the rule at all (`pre/` and a lowercase `.changeset/claude.md` count, the latter also through the content rules; `README.md` in either case, `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, dot-prefixed, nested and doubly-nested `.changeset/.changeset/` files do not), the identity shape checks (a flag left without a value now fails instead of parsing as the boolean `true`, asserted for owner, reviewer and approver) and the owner-history comparisons, the path a staged rename is reported under, and the order in which `drop` rejects its arguments. The changeset check is additionally invoked directly, with a valid base as the control, so its unresolvable-base message is pinned too. `docs/agents/workflow.md`, `commit.md`, `release.md` and ADR-0014 carry the updated contract.
