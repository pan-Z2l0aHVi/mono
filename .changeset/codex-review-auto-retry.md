CI 与文档变更，不涉及发包：`missing_coverage` 空壳结论不再需要人工重跑。`Codex Review Report` 的 `report-conclusion` 持有 `actions: write`，在 CI 已判红、产物为 `unreviewed / missing_coverage` 且「触发写回腿的 CI run attempt」与「写回腿自身 attempt」都为 1 时调用 `gh run rerun --failed` 一次。任一不可读或 CI 未判 `failure` 就跳过（评论标 `none`，要求先核对运行页 Summary 的原因、不要连续重跑），任一大过上限就停下转人工（标 `exhausted`）。双维度是必要的：人工 re-run 写回腿时事件 payload 仍是原始快照（CI run attempt 不变），只看前者会再 POST 一次重跑、突破「只一次」上限。上限取 1 的依据是每次重跑都会再触发一次 `workflow_run` 与模型腿，超过一次就变成反复烧模型而非恢复。`unusable_output` 与 `error` 仍保留「重跑整条 run」。结论评论按 `none` / `triggered` / `exhausted` / `failed` 四态写明恢复状态；业务异常统一收敛成 `failed` 档并写进 step output、`::error` annotation 与 Summary，进程级崩溃没写出 output 时由步骤 outcome 兜底，不会退回误导性的手动重跑指引。恢复状态的兜底判定放在可信脚本内，不依赖 Actions 表达式返回操作数的语义；判定顺序按「先排除不该恢复 → 再判上限」分层，避免 CI 已成功或字段不可读时误报 `exhausted`。脚本单测钉住双维度上限、分流、状态解析、编排层异常兜底与四态文案，编排断言钉住权限、步骤顺序、env 与可信子命令；`docs/agents/review.md` 与 ADR-0021 同步恢复指引、权限扩张理由和未采用的方案。
