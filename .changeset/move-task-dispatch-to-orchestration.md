Internal change: moves the requirement-splitting and task-dispatch layer out of this repo's documentation and into the herdr-projects orchestration layer. `AGENTS.md` no longer tells agents to split `packages/*` vs `apps/*` work themselves and no longer fixes a worktree path convention; `docs/agents/worktrees.md` is now scoped to the repo-side boundaries only (one owner and one implementation worktree per mutable task, the `pnpm install && pnpm run build` an executor must run before implementing or freezing, and the shared turbo cache), with worktree creation, placement and cleanup owned by the orchestration layer; `docs/agents/release.md` drops the deleted `Manager` role in favour of the aggregating task's owner; `docs/agents/task-packet.md` records that `Owner`, `Worktree` and `Base` come from the orchestration layer. Adds ADR-0021 recording that division.

Two decisions are recorded in ADR-0021. The T0 criterion "aggregated release or multi-worktree parallelism" is removed from the tiering table: it described an orchestration shape rather than a change's blast radius, so the same diff was T0 or T2 depending only on how many tasks happened to run beside it — parallelism no longer raises a task's tier on its own. And T0 review is now provided by a separate orchestration thread with its own worktree, checked out from the owner's branch with `--base`, so a reviewer neither enters the owner's worktree nor requires the owner to push early; the pre-authorized-operations list is deliberately left untouched, so push still needs per-instance authorization.

Deliberately unchanged: the T0/T1/T2 state machine and all `pnpm agent:task` subcommand semantics, the `diffHash` definition, the `alwaysOnChecks` allowlist, the two `.agents/checks/` policy checks, the Playbook and hotfix rules, and the pre-authorized-operations list. The orchestration layer retired by 6d7e1694 is not restored — no role contracts, handoff templates, pane sequencing or executor launch flags are written back. No published package is affected.
