# Test Authoring

## 何时加载

新增、修改、评审或体检既有测试，或判断一个改动该不该加测试时加载。测试框架、运行命令、环境与语言约定由宿主仓库决定；本 skill 只判断写什么、留什么与为什么。

## 只为真实回归买单

- 能说出具体回归风险才加测试；说不出，或只是为了提高覆盖率，不加。
- 优先扩展现有测试，不建功能重复或高度重叠的新测试。
- 优先覆盖业务逻辑、状态转换、用户交互、可访问性契约与关键用户流程。
- UI/UX 以用户可感知的行为、可访问性与关键视觉回归为准，不把设计决策全部转成自动化断言。

## 行为优先于实现

- 写面向行为的测试，不写面向实现的测试。
- 不断言具体 CSS 属性、像素尺寸、内部 class、内部状态或用户不依赖的 DOM 结构。
- 纯展示层变更默认不加单元测试。
- 展示层默认不加 snapshot；视觉回归只用于稳定且高价值的 UI。

## 稳定性与结构

- 测试必须稳定、可维护。容易 flaky 的测试不加，除非不稳定性本身就是要验证的产品行为。
- 用 Arrange、Act、Assert 组织；一个测试只验证一个行为；测试之间保持独立。
- 只在需要断言调用时使用带类型的 mock；等待确定性的生命周期信号，不用任意超时。
- 测试描述语言与命名遵循宿主仓库约定。

## 异步完成与隔离

- 等待本次操作承诺的最终效果，先注册观察再触发操作，并关联对应的目标或请求。入队、落库、消费者开始执行、首个 observer 回调分别只证明该阶段；跨阶段断言要等待其实际完成信号。
- helper 区分成功、失败、取消和超时。成功来自目标条件或完成信号，超时带当前阶段、耗时和最后读数失败。多阶段等待声明总预算或独立预算，调用链按该声明传递；每条退出路径释放 timer、observer、listener 和未完成的帧回调。
- 时间边界优先由可控时钟或调度器推进，再等待派生操作完成。真实计时、指针命中、模态、动画及内核通知需要原生集成时，保留对应测试，说明其无法由轻层证明的契约。
- 负向断言先证明触发进入目标路径，并界定观察边界。取消或卸载在途工作的用例还要先证明该工作已经启动，再推进到取消或完成的边界。固定次数的 microtask、稳定若干帧或一段安静时间只证明所观察的区间，不能替代仍在途工作的完成。没有封闭完成信号的真实集成，声明有限观察的范围和诊断。
- 测试或 fixture 的 owner 在成功、断言失败与操作抛错时恢复自己改变的共享状态，结束或取消自己启动的异步工作。进程退出或文件隔离不能代替同一文件内的实例清理。

## 测试的生命周期

- 代码或行为变化让测试失去价值时，删除或重构测试；不要为了让测试通过而改生产代码。
- 判一个测试还有没有价值，看它断言的主题是不是仍然存在的契约，而不是它写成什么语法形态；测颜色的数学表达式可能正是在测 token 契约。删之前先做一次变异，改不动任何东西的测试才是真的没在测。
- 保持行为不变的重构，先记录现有行为清单，确认保留或移除后再变更，并同步测试与文档。
- 精简或迁移测试时，记录重复或失效的具体理由，以及保留用例承接的行为。用能检出相应缺陷的反向验证支持承接关系，保留轻层无法证明的原生集成；不按用例总数或删测配额评价精简效果。
- 不删除、跳过或用空断言让检查变绿。失败时区分环境问题、既有失败与本次回归。

## 既有套件体检

体检判断的是既有用例还提供多少保护，不是用例数、覆盖率或写法风格。判据与「测试的生命周期」相同：改坏被测行为时它会红，才说明它在测。以下三类症状看着有测试、实际不提供保护，处置各不相同。

**同义反复（tautological）**

- 断言由被测实现自己产生：期望值与被测代码重复同一表达式，或同一个 helper、同一份输出同时充当输入与期望。实现改坏时两边一起变，测试不会红。
- 只断言「没有抛错」「返回真值」这类空断言，通常只证明执行路径没崩；只有「不抛错」本身就是该输入的唯一契约时才算有效，并要写清对应输入与路径。
- 处置是把期望值换成独立来源：fixture、手工推导的常量、协议样例，或真实依赖的已知输出。找不到不依赖实现的期望时，说明该位置没有可断言的行为，按「测试的生命周期」做变异验证后再改为更外层的测试或删除，不改生产代码迁就测试。

**对结构过度敏感**

- 断言绑死在内部函数名、调用顺序、私有字段、DOM 层级或 snapshot 全量输出上时，重构必红，真实行为回归却可能不红，因为它守的是当前编排而不是行为。
- 处置与「行为优先于实现」一致：把断言上移到用户可观察的输入输出、事件、可访问性语义与公共契约。只有需要证明调用发生时才引入 mock，并只断言与契约相关的参数和次数，不断言无关的先后与内部调用链。上移不到稳定契约、只反映当前分层的，按「测试的生命周期」删除或并入外层测试。
- 结构断言不都被清掉：契约字段、协议与序列化格式、生成物 schema、消费者依赖的导出形状本身就是被测对象，应继续精确断言，但锚定稳定的契约面，不锚定当前实现的分层。生成物的正确性由 generator 重建证明；`**/__screenshots__/` 与 `**/.vitest-attachments/` 是测试证据而非源码产物，snapshot 或视觉基线在重构后变红时，先判断它守的是否仍是稳定且高价值的契约；更新基线是独立的显式任务，不是体检的默认收尾。

**mock 与真实行为不符**

- mock 的返回形状、时序或错误语义与真实依赖不一致时，测试通过只证明 mock 自洽。常见形态：成功路径的 mock 永不 reject、超时或取消；字段比真实响应少；同步 resolve 抹掉真实的异步阶段；错误只用 `Error` 表示，而真实依赖返回错误码或结构化错误。带类型的 mock 只保证形状与类型一致，不保证时序与错误语义。
- 发现失真先对齐来源：从真实依赖的类型、schema、录制或契约测试取形状和时序，不凭印象补字段。
- 再按这条测试要证明的契约处置：证明消费逻辑（分支、重试、降级、状态转换）时，让 mock 忠实模拟依赖契约，并加 contract test 钉住 mock 与真实依赖的共同契约；证明依赖交互本身（重试、超时、取消、错误分类、顺序）时，改用真实依赖或宿主提供的集成层。外部服务、时钟、随机与网络故障仍需要可控替身，回到真实依赖不是默认答案。

处置之后，用「测试的生命周期」的变异方法验证结论：改坏实现应红，恢复应绿。体检的产出是保护力变化与理由，不是通过率。

## 验证证据

- 适用的测试与构建在实施阶段完成，不把首次运行留给 CI。
- 按影响选择范围：受影响的测试、必要的全量测试、构建，以及宿主要求的真实运行时验收。
- 记录实际命令、结果与未覆盖缺口；证据必须对应当前代码状态。
- 收窄范围后要用输出里的用例或文件计数证明收窄真的发生了；传给命令的路径参数不生效时，全量绿会被读成「这一档绿了」。
- 拔掉或短路一个检查后仍然全绿，只说明没有用例在证明它承重，不足以判定它可以删；承重要靠制造一个本该被它拦下、拔掉后才漏过去的失败来证明。
- 失败信息常被换成另一句，只 grep 原句会漏。要比总数，并把新旧两种措辞一起搜，改动前后背靠背各跑一次。
- 两方证据各执一词且数字对不上时，写「未查清」并继续核，不要挑一支信。

## 边界

- 测试框架、运行命令、环境、fixture 路径与测试语言属于宿主仓库。
- 浏览器与原生应用的取证纪律由宿主的运行时验证规则承担；本 skill 不把仿真测试当作真实运行时验收。
