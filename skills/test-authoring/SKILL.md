# Test Authoring

## 何时加载

新增、修改或评审测试，或判断一个改动该不该加测试时加载。测试框架、运行命令、环境与语言约定由宿主仓库决定；本 skill 只判断写什么与为什么。

## 只为真实回归买单

- 能说出具体回归风险才加测试；说不出，或只是为了提高覆盖率，不加。
- 优先扩展现有测试，不建功能重复或高度重叠的新测试。
- 优先覆盖业务逻辑、状态转换、用户交互、可访问性契约与关键用户流程。
- UI/UX 以用户可感知的行为、可访问性与关键视觉回归为准，不把设计决策全部转成自动化断言。

## 行为优先于实现

- 写面向行为的测试，不写面向实现的测试。
- 不断言具体 CSS 属性、像素尺寸、内部 class、内部状态或用户不依赖的 DOM 结构。
- 纯展示层变更默认不加单元测试。
- 展示层默认不加 snapshot；视觉回归只用于稳定且高价值的 UI。

## 稳定性与结构

- 测试必须稳定、可维护。容易 flaky 的测试不加，除非不稳定性本身就是要验证的产品行为。
- 用 Arrange、Act、Assert 组织；一个测试只验证一个行为；测试之间保持独立。
- 只在需要断言调用时使用带类型的 mock；等待确定性的生命周期信号，不用任意超时。
- 测试描述语言与命名遵循宿主仓库约定。

## 测试的生命周期

- 代码或行为变化让测试失去价值时，删除或重构测试；不要为了让测试通过而改生产代码。
- 保持行为不变的重构，先记录现有行为清单，确认保留或移除后再变更，并同步测试与文档。
- 不删除、跳过或用空断言让检查变绿。失败时区分环境问题、既有失败与本次回归。

## 验证证据

- 适用的测试与构建在实施阶段完成，不把首次运行留给 CI。
- 按影响选择范围：受影响的测试、必要的全量测试、构建，以及宿主要求的真实运行时验收。
- 记录实际命令、结果与未覆盖缺口；证据必须对应当前代码状态。

## 边界

- 测试框架、运行命令、环境、fixture 路径与测试语言属于宿主仓库。
- 浏览器与原生应用的取证纪律由宿主的运行时验证规则承担；本 skill 不把仿真测试当作真实运行时验收。
