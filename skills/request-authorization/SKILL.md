# Request Authorization

需要用户明确授权的操作，以**交互式弹窗**提交请求；纯文本提问等于请求尚未发出。弹窗是授权的载体：报告写正文，提问走弹窗。

项目文档定义了自己的授权机制时，以项目机制为准；本 skill 是缺省形状。

## 弹窗正文

选项之上，按顺序写清四项：

1. **什么**——一句话说明要执行的操作，或这次改了什么；
2. **为什么**——关联的 task、issue 或要解决的问题；
3. **怎么执行**——命令、影响范围、不可逆点；
4. **预期效果**——已验证的给结论，未验证的明说；再列风险、隐患和可替代做法，没有写「无」。

## 选项

把待决事项本身做成选项：推荐项放第一位并打标，每个选项都是真实可行的不同选择，保留自定义输入（弹窗工具内建的自由输入算）。四项说明与选项要求同时成立，请求才合规；缺任何一侧，重建弹窗再发。

## 同意语义

弹窗只是呈现选择，用户点了推荐项才是授权。沉默、超时或会话结束都使操作保持未授权；推荐项在用户选择前只是推荐。

## 回合收尾自检

结束回合前读最后一段：只要存在待授权事项，回合必须落在已提交的弹窗上。发弹窗，停在那里；弹窗之后的任何文字都会埋掉这个决定。

## 环境映射

用所在客户端的交互式问答组件（提供选项、推荐标注与自由输入的那类）；环境没有这类组件时，把四项说明、打标选项与「停下等待」写进纯文本——同形状，正文媒介。
