# Interweave 产品基线

- **状态**：已确认产品基线
- **日期**：2026-08-15
- **适用阶段**：首个可用版本（v1）
- **权威性**：本文件定义 Interweave 当前产品边界。技术方案和实现必须遵守它；需要改变已决原则时，先更新本文件，涉及长期领域边界时再新增 ADR。

## 产品定位

Interweave 是面向普通个人用户的、本地优先的个人资源关系库。它帮助用户持续纳入散落在文件系统和网络中的资源，以后能够找回、理解并探索它们的联系。

Interweave 不是文件管理器、书签工具、云盘、内容播放器、Markdown 工作台或通用知识库。它不接管原始内容的存放与编辑，而是在外部内容之上保存用户的组织上下文。

## 用户与核心任务

首批用户是持续积累文件、网页链接、图片、音视频等数字资料的普通个人用户。

首要任务是持续整理：用户可在需要时把少量资源主动纳入库中，补充语义标签和简短个人说明，并在之后通过资源库、搜索和 Map 找回或理解资源。

不提供首次资料整理、全盘扫描、文件夹监听、自动归类或自动迁移。用户添加资源时可以立即加标签，也可以稍后处理；未标记资源不会阻塞使用。

## 核心概念

### Resource

**Resource** 是用户希望长期找回、理解或使用的一个原子概念对象。它保存独立标题、短备注、语义标签、来源与来源状态。

Resource 不是文件夹、项目容器、内容页面或资源集合；一个 Resource 不包含其他 Resource。不同版本的文件或链接默认是不同 Resource，v1 不管理版本历史或版本关系。

### Source

**Source** 是访问 Resource 的外部入口。v1 支持本地文件和单个 URL，后续可以扩展远程文件、RSS、网盘或 NAS。

一个 Resource 必须至少有一个 Source，可以有多个同类型或不同类型的 Source，并恰有一个首选 Source；Source 是否 `available` 不影响该约束。新建 Resource 时首个 Source 自动成为首选，之后新增 Source 不自动切换。多个 Source 只表示同一 Resource 的备用或替代访问入口，不承担版本管理。用户可以从已有 Resource 中补充 Source、切换首选 Source；每个 Source 都提供一键替换入口，替换只影响该 Source 自身，保留其添加顺位和首选角色，不影响 Resource 或其他 Source，无需手动删除再添加；删除首选 Source 时按添加顺位选择最早添加的剩余 Source 作为首选。v1 不合并两个已经独立创建的 Resource。

v1 不对 Source 做全局去重：无论是新建 Resource、补充 Source 还是一键替换，即使文件路径或 URL 与既有 Source 完全相同，也照常执行本次操作；App 不定位、不拒绝、不合并、不转移，是否整理由用户自行管理。文件仍按规范化绝对路径保存，Windows 路径大小写不敏感；URL 仅接受绝对 `http`/`https` URL，去除输入两端空白，并规范化 scheme、host、默认端口和空 path，保留 path 大小写、query 与 fragment。URL 抓取可跟随重定向直至最终响应，不设重定向次数上限，但整个抓取受 10 秒总时限约束；Source 始终保存初始 URL，不自动改写为最终 URL。即使多个初始 URL 最终指向同一 URL 或内容，它们仍是多个 Source。

### 语义标签

**语义标签** 是用户为 Resource 添加的扁平、可复用的内容意义，例如 `东京`、`旅行`、`摄影`、`灵感`。

标签没有父子、路径、继承、标签间显式关系或直接资源关系。Resource 之间的可视关联只由共享语义标签派生。

文件/来源类型、来源可用状态、最近添加等是系统元数据，不是语义标签，不参与 Map。

### Map

**Map** 是从 Resource—语义标签归属关系中提炼出的资源关系地形图，不是全量知识图谱或手工画布。

它用于发现主题群、跨主题桥梁、孤立资源和低质量标签，并始终解释资源为何关联：它们共享哪些语义标签。

## 首版体验

### 资源库

资源库是默认首页，使用紧凑列表与小缩略图平铺所有 Resource。它负责新增、直接搜索、查看详情、打开来源与基础编辑；标签语义浏览不在资源库中分类或筛选，而集中在 Map。

用户可搜索独立标题、短备注、语义标签、来源文件名、URL 和站点基础信息。不索引文档全文、网页正文、图片文字或音视频内容。

### 手动纳入与来源

v1 仅提供 App 内入口：文件选择、拖放文件与粘贴 URL。本地文件在纳入时必须先执行一次轻量 `stat` 检查，成功以 `available: true` 写入，失败以 `available: false` 写入；两种结果均创建，但不读取文件内容或计算 hash。URL 在纳入时必须先完成一次基础元数据抓取，再写入 Resource 与 Source；抓取成功以 `available: true` 写入，任一失败或超时以 `available: false` 写入，但都不阻塞创建，用户仍可维护独立标题。后续非元数据数据加载不阻塞首次纳入。

不提供浏览器扩展、系统右键入口、文件夹监听、全盘扫描、RSS 订阅或自动采集。RSS 在 v1 仅可作为普通 URL 保存。

所有文件类型都可被纳入和打开；预览按高价值常见类型渐进支持。图片、网页基础信息和少量常见格式优先，其他类型交给系统默认应用打开。

### 标题、备注与标签维护

Resource 标题默认仅在首次纳入时取自首个文件名或 URL 展示信息；首个 URL 没有可用页面标题时使用其规范化 hostname，文件则使用文件名。用户可在 Interweave 内修改，不影响外部文件名或 URL。首次纳入后，新增 Source、刷新 URL 元数据、重定向结果或任何自动处理均不得改写 Resource 标题。

Resource 仅允许简短备注，用于保存个人上下文并参与搜索；不提供 Markdown 正文、块编辑器、嵌入内容、子页面或长文写作。

添加标签时优先建议已有标签，用户可即时新建。新建前必须将标签名称标准化（去除首尾空白、折叠内部连续空白、Unicode NFC 规范化、拒绝空字符串、保留原始大小写且不剥除标点与连字符）；若标准名称已存在，则自动复用既有标签，不创建同名标签。标签不支持别名，不自动判断或合并语义相近的不同标签。v1 不提供全局标签管理面板，不提供全局标签重命名或全局删除入口。标签操作仅在单个 Resource 上进行增删；用户若需调整标签，可在具体 Resource 上移除旧标签并添加新标签。

### Source 状态与移除

Interweave 引用外部内容，不复制、移动、重命名或删除原始文件、网页或远程对象。

Source 以 `available: boolean` 保存持久化可用性：`true` 为可用，`false` 为不可用；不设 `unknown` 或独立状态枚举。当 Source 不可用时，Resource、标题、备注、标签和 Map 关系必须保留。用户可手动添加、替换 Source 或切换首选 Source；v1 不自动扫描、定位或修复失联文件。

用户从 Interweave 移除 Resource 时，只移除库内记录；不影响任何外部内容。

### Map

Map 默认先展示由标签共现形成的主题群。全局视图优先显示强关联，较弱关系仅在用户聚焦标签或 Resource 时出现。

选择一个标签后，Map 展开直接拥有该标签的 Resource 节点及其其他语义标签，供用户逐层探索。用户可在 Map 中打开 Resource、查看共享标签、打开 Source，并对单个 Resource 快速增删标签；Map 不承担拖拽排版、批量整理、手工连线或复杂画布编辑。

未标记 Resource 不进入 Map 网络，以 Map 外的未连接资源入口或数量提示呈现。

## 数据、平台与联网边界

v1 支持 Windows 和 macOS，但每台设备维护独立本地资源库。使用不要求账户、登录、云服务、自动跨设备同步、团队协作或共享权限。

v1 始终从新的本地资源库开始，不读取、迁移、修改或删除 2026-08-15 重置前的旧 Interweave 库。旧 `Item`、路径式标签、监听、Repair 和 MCP 数据不映射到 Resource、Source 或语义标签。

URL 的基础元数据仅在添加时或用户显式刷新时联网读取。添加操作必须等待该次基础元数据抓取完成或 10 秒总时限到达，再以 `available: true` 或 `available: false` 写入；该时限覆盖整条重定向链，且不另设重定向次数上限。只要得到可访问的 HTTP 成功响应且抓取流程正常完成，即使目标不是 HTML，或展示元数据字段缺失，也写入 `available: true`。后续非元数据数据加载不阻塞该写入。v1 不做后台轮询、定期可用性检查、自动标题/缩略图更新，也不把远程内容变化解释为版本。

## Agent 与 MCP 路线

MCP 对产品重要，但不进入首个可用版本。资源库必须先在纯人工使用下完整成立。

后续 MCP 的第一阶段优先只读检索、读取 Resource 上下文与解释 Map 关系；之后才考虑经用户确认的标签建议或批量整理。Agent 不得静默改变资源网络、移动外部内容或取代人工确认。

## 明确非目标

- 文件系统整理、移动、复制、重命名或删除原始内容。
- 内容托管、内部文档、Markdown/富文本工作台。
- Resource 版本管理、版本历史、内容差异或自动合并。
- 文件全文索引、网页全文存档、OCR、音视频转写。
- 父子标签、路径标签、标签别名、显式标签关系、直接 Resource 关系。
- 全局标签管理面板、全局重命名/删除标签、自动语义合并或同义词图谱；标签维护仅在单个 Resource 上进行。
- 自定义条件构建器、保存筛选、智能集合。
- 全盘扫描、自动分类、自动修复、自动采集。
- RSS 原生订阅、网盘/NAS 集成、云同步、多用户协作。
- 添加或替换时自动检测、拒绝、定位、合并或转移重复 Source；未来用户主动触发的重复扫描另行评估。
- 从 2026-08-15 重置前的旧 Interweave 库自动迁移或建立兼容层。
- 首版 MCP、Agent 自动整理或 Agent 写入权限。

## 产品验收场景

1. 用户在 App 中拖入任意文件或粘贴 URL；Resource 立即出现在资源库中，URL 读取失败也不阻塞。
2. 用户可为 Resource 添加多个语义标签，或暂时不添加；未标记 Resource 不出现在 Map 网络。
3. 两个 Resource 共享标签后，用户可在 Map 局部探索中看到关系并知道共享了哪些标签。
4. 用户可从 Resource 详情补充多个文件或 URL Source，并切换首选 Source；即使重复添加完全相同的 Source，也会按本次操作独立保留，不定位或合并已有 Resource。
5. Source 失联后，Resource 的标题、备注、标签和 Map 关系仍存在，用户可手动补充或替换 Source。
6. 用户在单个 Resource 上增删标签会即时更新该 Resource 的详情、搜索和 Map 关系，且不影响外部内容。
7. 用户无需账户即可在任一单独的 Windows 或 macOS 设备完成全部基础流程。
